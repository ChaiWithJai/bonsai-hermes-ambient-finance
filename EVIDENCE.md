# Evidence and remaining integration

The fixture and the generated `runs/2026-09-25-nightly.json` establish the numeric example. A publishable copy of the daily run is in `evidence/daily-run.json`. The Python test suite checks the calculations and the gates against independent expected values. The two PDF files and two CSV files are fictional analyst sources generated by `make_mock_sources.py`.

The first nightly run has `model_status: not_requested`. A later daily run on the same sample date called the shared Ternary Bonsai 2 27B server through Hermes and this demo's loopback proxy. The captured exchanges contain a call to `finance_latest_run`, two calls to `finance_position`, and a final model answer. The final answer identified FIC-HEL as the largest position, gave the $640,800 total, applied the $70,232 downside and $54,088 upside assumptions, and flagged R-MER as 138 days old.

The Hermes CLI did not exit after the final model response and the wrapper timed out after 360 seconds. The saved daily run therefore has `model_status: model_final_observed_cli_timeout`, and the raw exchange is retained only in the local `exchanges/` directory. That attempt did not establish a successful CLI return. The publishable `evidence/captured-model-draft.md` contains the actual final model text with this limitation stated.

The deterministic evaluator passed 11 coverage and false-claim checks on the captured draft. Its result is in `evidence/evaluation.json`. MLflow trace `tr-ac768cad07c06ad8bb1ded2fee579f36` in experiment 42 has status OK and a `evaluate_captured_finance_draft` span. It traces the offline evaluation of the captured draft, not the live Hermes process. The trace ID and scope are recorded in `evidence/mlflow-trace.json`.

A later retry of the daily work item returned exit code zero, but the model repeated the previous timed-out draft's obsolete status because that draft was still present in the tool-readable work item. The wrapper now archives each prior attempt before retrying and clears earlier model text and status from the tool input. The prompt asks for a draft of at most 250 words about the largest exposure and stale-research position. This is a harness and evidence-isolation correction, not a change to model weights or serving parameters.

The independent nightly work item `2026-09-25-nightly` then completed through Hermes and local Bonsai with exit code zero in 56.9 seconds. Session `20260926_140712_c09d15` called `finance_latest_run` once and `finance_position` twice. Its 182-word draft identified FIC-HEL and R-MER, gave both scenario IDs and amounts, and left the stale-research decision to a human. `evidence/nightly-session.json` records the prompt, tool names, result hashes and final answer without hidden reasoning or raw tool outputs. The publishable work item and draft are `evidence/nightly-run.json` and `evidence/nightly-model-draft.md`. MLflow experiment 42 trace `tr-fcf4010454b4b66c0b27302cd8752ce7` logged 14 of 14 offline checks, including clean CLI exit, length and absence of the old timeout claim. `evidence/mlflow-nightly-14-checks.jpg` shows that trace. These checks do not judge investment quality or trace the online model call.

On September 26, a per-user macOS LaunchAgent was installed to call `scheduler.py --once` at login and every five minutes. `launchctl` reported one completed run and exit code zero. Its first scheduled execution wrote `2026-09-26-daily.json` with `status: blocked` and `model_status: skipped_data_gate`, because the September 25 fixture prices were not current for September 26. The publishable copy is `evidence/scheduled-daily-blocked.json`; `evidence/launchd-status.json` records the installed job's observed status. This proves the scheduler executed and respected the data gate. It does not prove unattended model inference after a reboot: this LaunchAgent does not supervise the Bonsai server or the sampling proxy, and no fresh-data scheduled model run has completed.

There is no Slack exchange, Google Sheets write, online MLflow model trace, human approval or measured optimization result for this ambient finance workflow. The files named `mock-drive` and `mock-sheets` are local stand-ins, not connected cloud accounts. The research index contains pre-entered summaries, and the program checks source file presence rather than extracting facts from the PDFs or CSV files. The review log records entered names without authentication and cannot represent an actual portfolio manager's approval.

For a full filmed run, capture a connected intake source, the actual Hermes result and an online model trace. A finance team would also need a governed market-data adapter, access control for reviewers and its own portfolio accounting system before using this pattern on real information.
